# ADR 001: Android 首次可信配对

状态：已实施；真机与远端 CI 证据及限制见 [第三里程碑报告](trusted-pairing-report.md)。日期：2026-10-16。

## 威胁模型与信任根

本机普通应用可以抢占 loopback 端口、提供任意证书、伪造 HTTP 响应或触发配对。
网页内容也不能获得 Root、主 Secret、证书指纹或任意网络访问。Root/系统被攻破、
官方签名私钥泄漏和 Android Binder/应用沙箱失效不在本协议可以防御的范围。

服务端信任根不是端口、首次 TLS 证书或 HTTP 响应，而是 Android Binder 的 UID 0
身份及应用私有存储。反向交付的信任根是模块内固定的官方 APK 签名指纹、用户 0、
独占 UID 和固定非导出 Provider。V9 直接复用 V8 安全源码，不建立第二套 TLS 客户端。

## 调用链

1. 原生客户端先读取私有 ConnectionStore；存在资料时直接使用精确证书钉扎的 HTTPS。
2. 缺失资料时，由原生传输向固定 loopback 地址发送 POST `/api/v1/auth/provision`，
   正文固定为 `{}`，不带 Authorization、Cookie、Origin、设备信息或前端输入。
3. 该触发连接尚不能验证安装证书，只允许发送上述无敏感资料的请求，不复用其连接
   执行业务，不跟随重定向、不自动重试，也不从响应解析连接资料或建立身份。
4. 真正 Worker 通过 Root DEX 验证固定官方包的当前签名、用户、UID 和 Provider，
   绑定后再次核对 Provider 身份，以 Binder 私有调用交付安装资料。
5. Provider 只接受 Binder UID 0，严格校验资料后原子写入 no_backup，并更新共享缓存。
   客户端只接受这次新的、地址匹配的私有交付；HTTP 成功、错误或响应正文均不是凭据。
6. 触发请求有界取消。得到可信交付后先关闭触发 Call，再用另一套精确证书 SHA-256
   与主机名验证的客户端发送 Bearer 业务读取。任意监听者不能诱导 Bearer 泄漏。

## 并发、恢复和拒绝

同一传输的首次连接串行并在锁内复查缓存。Go 的交付有独立互斥、成功 30 秒冷却及
失败有界退避。恶意应用最多造成有界资源消耗或拒绝服务，不能更改固定交付目标。
初始响应不能伪造错误提示、改变地址或覆盖资料；没有交付时只返回本地脱敏连接错误。

已认证请求的真实 401 或证书身份失败只失效自身凭据版本，不删除并发的新交付。
后续连接可再次触发可信交付；不自动重发已经执行的写入。显式重连失败保留旧资料。
证书替换必须先拒绝原请求，再由新的 Root 私有交付建立新身份，不能信任错误证书。

无模块、错误监听、无官方管理器、签名不匹配、Provider 被替换或交付超时均失败关闭。
取消或 Activity 销毁只取消本次原生任务；Root 已开始的交付可能完成，但不向旧页面回传资料。

## 权限与取舍

不增加 IPC 方法、Shell/Root/文件权限、HTTP 任意 URL 或 Go 持久化字段。
JS 仅能读 info/service 和订阅已授权事件。Go 的 POST 是原生内部配对触发，不是 JS
获得了业务写入能力。隔离调试包不在官方固定目标内，首次配对失败是预期结果。

拒绝 TOFU、手动粘贴主 Secret、信任响应中的证书以及把证书验证关闭后直接请求业务。
保留现有私有 Provider 的厂商兼容限制；不通过扩展导出权限或写应用目录绕过 Binder。

## 必须验证

自动化覆盖恶意响应、无交付、交付与响应竞态、并发/取消、证书和主机名拒绝、401
失效及重配对。设备分别验证干净连接存储、错误签名、Worker/核心重启与 Activity
销毁重建。测试模拟不代替真机；缺失前提逐项记录，不能视为验收通过。
