# 设计理念

NetProxy 希望把 Android 上复杂的透明代理能力整理成一套可长期使用、也能深入控制的工具。

## 默认就能用

常用场景应有可工作的默认值。用户可以先完成导入、选择和启动，再按需要理解 DNS、路由、eBPF 和 API，而不是在第一次使用前被迫掌握全部底层概念。

## 状态说清楚

- 持久配置和运行状态分开显示。
- 配置保存前完整检查，失败时保留上一份有效内容。
- 服务、订阅和运行时同步返回明确状态，不用“命令没报错”代替成功。
- Android 管理器、WebUI 和 CLI 使用同一管理入口，避免三套说法。

## 日常操作留在界面

节点、订阅、分应用代理、Wi-Fi 策略和日志等高频操作优先在 Android 管理器中完成。CLI 和配置文件保留给自动化、无管理器环境与高级调整，不把它们当作普通用户的必经之路。

## 高级能力不隐藏

管理器只展示适合日常使用的选项，但不会删除底层配置能力。需要时仍可检查或调整 sing-box 静态配置、eBPF 参数、路由规则和 DNS 行为，并通过日志和控制面板观察结果。

## 不制造第二个代理核心

NetProxy 负责 Android 模块生命周期、配置、节点、订阅和管理入口；实际代理与 eBPF 入站由 sing-box 承担。模块不会再维护一套平行的数据面或用界面状态替代核心真实状态。
